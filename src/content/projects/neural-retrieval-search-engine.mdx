## Summary

**Problem**
- *Background.* Nexus++, NAVER's in-house search engine, runs neural retrieval with [ColBERT](https://arxiv.org/abs/2004.12832), a multi-vector model: every document becomes up to 100 vectors, so the index holds 50 billion+ vectors.
- *Motivation.* The business wanted better search quality while the machine budget stayed flat.
- *Problem definition.* Serve the same neural search faster on the same hardware, with the existing model and the existing vectors.
- *Why it's hard.* The engine is the first stage of the ranking pipeline and must answer in under 100 ms, and ColBERT scoring took half of that. The academic answers ([ColBERTv2](https://arxiv.org/abs/2112.01488), [XTR](https://arxiv.org/abs/2304.01982)) assume retraining, which was off the table.

**Action**
- Replaced the full ColBERT score with an approximate score built from similarities the retrieval step had already computed.
- Closed the quality gap with **MSI++**, our extension of XTR's missing-similarity imputation.

**Result**
- Average response time −50%, peak throughput 2×.
- Quality held at 95–97% of full ColBERT across nDCG, MRR, recall and precision.
- Shipped with no model change and no new hardware. Presented at DAN24, NAVER's engineering conference.

## Engineering details

### How ColBERT scoring works in the engine

A query becomes a few vectors, a document up to 100. Retrieval runs one single-vector ANN search per query vector (top-K each) and takes the union of the documents hit, well under 0.01% of the corpus. Ranking then computes the full ColBERT score for each candidate: for every query vector, the maximum similarity to any document vector, summed. Retrieval and ranking each took roughly half of the latency budget.

### Approximate score: rank with what retrieval already computed

A document vector that was not retrieved for a query vector is, by construction, not among that vector's nearest neighbours, so it rarely wins the max. Dropping those pairs and summing only the similarities the ANN step already produced gives an approximate score ([ColBERTv2](https://arxiv.org/abs/2112.01488), Santhanam et al. 2022; [Macdonald and Tonellotto 2021](https://arxiv.org/abs/2108.11480)) at a fraction of the cost. Against full ColBERT it kept 93–97% of quality while ranking time fell from about 50 ms to about 5 ms and peak throughput rose 1.7×.

### From XTR to MSI++ (ours)

[XTR](https://arxiv.org/abs/2304.01982) (Lee et al. 2023) goes further. The approximate score still computes a few extra similarities for the retrieved pairs; XTR uses only the similarities the ANN search has already cached and computes nothing new, so the remaining 5 ms disappears as well. When a query vector retrieved nothing from a document, that term of the score is undefined.

- **MSI (from XTR).** Missing Similarity Imputation fills the gap with the similarity of the top-K-th vector retrieved for that query vector. Any unretrieved document vector is at most that similar, so this is an upper bound and the imputed score is never below the true ColBERT score. XTR pairs this with retraining the model; we used the imputation alone.
- **MSI++ (ours).** The first lever is to retrieve more candidates so fewer similarities go missing: raising top-K up to the HNSW ef parameter costs no throughput. Some documents stay over-scored even then, because the plain upper bound still over-rewards documents with several missing similarities. MSI++ covers them by multiplying the imputed value by a penalty α (0 < α < 1), tuned to α = 0.7, so the score approximates rather than bounds the true one.

MSI++ is the model we shipped; in the DAN24 talk it is presented under the name NAVER-1.
